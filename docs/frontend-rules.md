# Правила верстки проекта

1. Верстаем обычными HTML, CSS и JS, без сборщиков и фреймворков.
2. Один экран — одна HTML-страница в папке `web`.
3. Все обращения к серверу идут через `web/js/api.js`. Внутри страниц запросов
   быть не должно.
4. Цвета, шрифты и размеры берём только из `web/tokens.css`. Новых значений не
   добавляем.
5. Папку `server` не трогаем. Если для экрана не хватает данных, сначала говорим
   об этом мне.
6. `web/` — рабочий клиентский интерфейс. `test-frontend/` — только отладочный
   SPA для проверки API, его не используем как основу новых клиентских экранов.
7. Ошибку от API показываем клиенту текстом на экране, а не только в консоли.
8. Админ-панель теперь верстаем: её экраны А1–А4 описаны в карте экранов, и
   к ним применяются те же правила 1–7. Экраны мастера пока не верстаем.
9. Доступ к админ-разделу проверяет сервер: `GET /api/admin/access` отдаёт роль
   `admin` только администратору, остальным `403`. Внутри экрана проверка
   повторяется на клиенте (`web/js/admin.js`): без роли показываем сообщение
   «Этот раздел только для администраторов», а не пустой раздел.

---

Перед версткой нового экрана посмотрите его строку в карте экранов:
[`docs/ui-map.md`](ui-map.md). Там указано, какой файл в `web/` соответствует
экрану, что он показывает, какие эндпоинты дают данные и вызываются кнопками и
куда ведут переходы. Детали подключения уже собранных клиентских экранов — в
[`docs/frontend-log.md`](frontend-log.md).
