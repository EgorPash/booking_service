# Карта клиентских экранов

Клиентский интерфейс собран в `web/` на обычных HTML, CSS и JS, без сборки.
Все запросы идут через `web/js/api.js`; общая шапка подключается из
`web/js/header.js`. Исходный макет `booking-prototype/` использован при вёрстке
и удалён; ниже — актуальные экраны проекта.

Собрано **8 экранов клиента**. Админ-панель появится в следующей итерации:
backend-эндпоинты `/api/admin/*` уже есть, клиентских страниц для них пока нет.

## Экраны

| № | Экран | Файл | Что показывает | Данные (GET) | Действия (мутации) |
|---|---|---|---|---|---|
| 1 | Лендинг | `web/index.html` | Hero-блок, услуги, мастера, адрес и часы студии; переходы в запись | `/api/studio`, `/api/services`, `/api/masters` | — |
| 2 | Авторизация | `web/auth.html` | Вход, регистрация, выход, текущая сессия; возврат на `next` | `/api/auth/me` | `/api/auth/login`, `/api/auth/register`, `/api/auth/logout` |
| 3 | Запись | `web/booking.html` | Четыре шага: услуги, мастер, дата, время; несколько услуг, итог, ближайшие окна | `/api/services`, `/api/masters`, `/api/studio`, `/api/masters/:id/slots` | — |
| 4 | Подтверждение | `web/confirm.html` | Данные клиента, комментарий, таймер удержания, сводка визита, создание записи | `/api/auth/me`, `/api/services`, `/api/masters`, `/api/studio`, `/api/bookings/my`, `/api/holds/:id` | `/api/holds` (POST/DELETE), `/api/bookings` (POST) |
| 5 | Запись оформлена | `web/success.html` | Номер, статус, услуги, мастер, дата, время, длительность и итог | `/api/bookings/:id` | — |
| 6 | Личный кабинет | `web/dashboard.html` | Активные записи и история, счётчики, ближайший визит, пустые состояния | `/api/auth/me`, `/api/bookings/my` | — |
| 7 | Детали записи | `web/booking-details.html` | Полная карточка, предупреждение о поздней отмене, перенос и отмена | `/api/auth/me`, `/api/bookings/:id` | `/api/bookings/:id/cancel` |
| 8 | Перенос записи | `web/reschedule.html` | Фиксированные услуга и мастер, календарь, свободные окна, новое время | `/api/auth/me`, `/api/bookings/:id`, `/api/studio`, `/api/masters/:id/slots` | `/api/bookings/:id` (PATCH) |

Подробные поля ответов и особенности экранов — в
[`docs/frontend-log.md`](frontend-log.md).

## Общая шапка

- **Файлы:** `web/js/header.js`, `web/css/header.css`.
- **Показывает:** логотип, «Главная», «Записаться», «Кабинет»; для гостя —
  «Войти» и «Регистрация», для вошедшего — имя/инициалы и «Выйти». На узких
  экранах ссылки убираются в меню-гамбургер.
- **Данные:** `GET /api/auth/me`, `GET /api/bookings/my`.
- **Действие:** `POST /api/auth/logout`.
- **Заглушки:** ссылки «Профиль» и «Уведомления» ведут на `profile.html` и
  `notifications.html`; этих страниц в текущей итерации нет.

## Основные переходы

1. **Лендинг → Запись.** Выбор услуг, мастера, даты и времени.
2. **Запись → Подтверждение.** Перед созданием записи клиент вводит данные,
   слот удерживается на время оформления. Если клиент не вошёл, его отправляет
   на `auth.html?next=confirm.html`.
3. **Подтверждение → Запись оформлена.** После успешного `POST /api/bookings`
   открывается `success.html` с номером и деталями.
4. **Кабинет → Детали.** Из карточки записи можно открыть детали, перенести
   будущую запись или отменить её.
5. **Детали → Перенос.** Услуга и мастер фиксированы, меняются только дата и
   время.

## Вне текущей итерации

- **Админ-панель** — следующая итерация: записи, услуги, мастера, график и
  настройки студии. API `/api/admin/*` уже реализован.
- **Профиль клиента** — отдельного экрана нет; имя и телефон приходят в
  `GET /api/bookings/my`.
- **Уведомления** — отдельного экрана и модели уведомлений нет.
- **Экраны мастера** — в текущую клиентскую карту не входят.

## Ограничения текущего API

- `GET /api/masters/:id/slots` возвращает только свободные окна; занятые окна
  интерфейс не рисует.
- Список доступных дат не отдаётся одним запросом: календарь собирает его
  перебором дат.
- Отдельного `GET /api/services/:id` нет; карточка услуги берётся из общего
  списка.
