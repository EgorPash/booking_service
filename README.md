# Lumi Beauty Studio — сервис онлайн-записи

Учебный проект сервиса онлайн-записи для небольшой студии красоты:
REST API на Node.js + SQLite и готовый клиентский интерфейс на HTML, CSS и JS.

Клиентские экраны собраны в `web/`: лендинг, вход и регистрация, запись,
подтверждение, успешная запись, личный кабинет, детали и перенос. Админ-панель
появится в следующей итерации.

## Состав репозитория

| Папка | Что это |
|---|---|
| `server/` | Backend: HTTP API (`node:http`), база SQLite (`node:sqlite`), миграции и сид. Сторонних зависимостей нет. |
| `web/` | Клиентский интерфейс: HTML, CSS и vanilla JS без сборки. Все запросы идут через `web/js/api.js`. |
| `test-frontend/` | Отладочный SPA для ручной проверки API: отдаёт статику и проксирует `/api` на backend. Не является частью продукта. |
| `docs/` | Документация по API, базе данных и клиентским экранам. |

## Что нужно установить

Единственное требование — **Node.js**. Всё остальное уже есть в системе или не требуется.

- **Node.js >= 22.13.0**, рекомендуется **Node 24 LTS**.
  Именно начиная с 22.13 встроенный модуль `node:sqlite` доступен **без**
  экспериментального флага `--experimental-sqlite` (в 22.5 он был за флагом).
- **npm** — ставится вместе с Node.js.
- **Git** — только чтобы склонировать репозиторий. Можно и без него, скачав ZIP.

> **Зависимостей у проекта нет.** `npm install` запускать не нужно — ни в
> `server/`, ни в `test-frontend/` нет сторонних пакетов, а `web/` состоит из
> статических файлов. Все команды работают сразу после установки Node.js.

### Установка Node.js

1. Скачайте **Node.js 24 LTS** с официального сайта: <https://nodejs.org/>.
2. Установите со всеми настройками по умолчанию.
3. Откройте **новый** терминал и проверьте версию:

   ```bash
   node -v
   npm -v
   ```

   `node -v` должен показать `v22.13.0` или выше (например, `v24.x.x`).

   Альтернатива — менеджер версий: в корне есть файл `.nvmrc` с версией `24`,
   поэтому после установки `nvm` достаточно выполнить `nvm install` и `nvm use`.

## Быстрый старт (с чистого листа)

Всё выполняется из **двух терминалов**: в одном — API, в другом — отладочный
фронтенд для проверки запросов.

**1. Получите код.**

```bash
git clone https://github.com/EgorPash/booking_service.git
cd booking_service
```

Если Git не установлен — скачайте ZIP-архив репозитория и распакуйте его.
Запомните полный путь к папке `booking_service` — он понадобится во втором
терминале на шаге 4.

**2. Подготовьте базу данных** (миграции + тестовые данные).
Файл базы `server/data/app.sqlite` в Git не хранится, поэтому его нужно создать:

```bash
cd server
npm run db:reset
```

**3. Запустите API** (оставьте этот терминал открытым):

```bash
npm start
```

Увидите: `API запущено: http://localhost:3000 (NODE_ENV=development)`.

**4. Во втором терминале запустите отладочный фронтенд.** Новый терминал
открывается в домашней папке, поэтому сначала перейдите в папку проекта
(подставьте свой путь):

```bash
cd "полный/путь/к/booking_service/test-frontend"
npm start
```

Увидите: `Тестовый фронтенд: http://localhost:4000`.

**5. Откройте <http://localhost:4000>** и войдите под одним из тестовых аккаунтов.

### Тестовые аккаунты (создаются командой `db:reset`)

| Роль | Email | Пароль |
|---|---|---|
| Администратор | `admin@lumi.studio` | `Admin123!` |
| Мастер | `master@lumi.studio` | `Master123!` |
| Клиент | `client@lumi.studio` | `Client123!` |

Админский аккаунт пока нужен для API и отладочного SPA: отдельного интерфейса
админ-панели ещё нет.

### Клиентский интерфейс

Рабочие экраны лежат в `web/` и не требуют сборки. Они обращаются к `/api`
относительно своего origin, поэтому открывать их через `file://` нельзя: папку
`web/` нужно отдавать статическим сервером с того же origin, где доступен API,
либо проксировать `/api` на backend. `test-frontend/server.js` показывает, как
устроен такой прокси, но отдаёт отладочный SPA, а не `web/`.

Собраны экраны:

| Экран | Файл | Что делает |
|---|---|---|
| Лендинг | `web/index.html` | Услуги, мастера, адрес и часы студии; переходы в запись и кабинет. |
| Авторизация | `web/auth.html` | Вход, регистрация, выход; возврат на `next` после входа. |
| Запись | `web/booking.html` | Четыре шага: услуги, мастер, дата, время; выбор нескольких услуг и ближайшие окна. |
| Подтверждение | `web/confirm.html` | Данные клиента, комментарий, удержание слота и создание записи. |
| Запись оформлена | `web/success.html` | Номер, услуги, мастер, дата, время, длительность и итог. |
| Личный кабинет | `web/dashboard.html` | Активные записи и история, ближайший визит, переходы к деталям. |
| Детали записи | `web/booking-details.html` | Полная карточка, предупреждение о поздней отмене, перенос и отмена. |
| Перенос | `web/reschedule.html` | Новые дата и время для той же услуги и мастера. |

Общая шапка подключается из `web/js/header.js` на всех страницах. Подробная
таблица «экран → эндпоинты → поля ответа» — в
[`docs/frontend-log.md`](docs/frontend-log.md).

**Админ-панель появится в следующей итерации.** Backend-эндпоинты
`/api/admin/*` уже реализованы, но клиентских страниц для них пока нет.
Ссылки «Профиль» и «Уведомления» в шапке — заглушки: этих экранов в текущей
итерации тоже нет.

## Команды

Все команды ниже выполняются из папки **`server/`** (там лежит `package.json`):

| Команда | Что делает |
|---|---|
| `npm start` | Запускает API на порту `PORT` (по умолчанию `3000`). |
| `npm run migrate` | Применяет неприменённые миграции из `server/src/db/migrations/`. |
| `npm run seed` | Заливает/обновляет тестовые данные (повторный запуск не создаёт дубли). |
| `npm run db:recreate` | Удаляет файл базы и создаёт заново только схему (без тестовых данных). |
| `npm run db:reset` | Удаляет файл базы, применяет миграции и заливает тестовые данные. Основная команда первичной настройки. |

В папке **`test-frontend/`**:

| Команда | Что делает |
|---|---|
| `npm start` | Отдаёт статику на порту `FRONTEND_PORT` (по умолчанию `4000`) и проксирует `/api/*` на `API_ORIGIN`. |

> `db:recreate` и `db:reset` удаляют файл базы. При `NODE_ENV=production` они
> заблокированы (нужен явный `ALLOW_DESTRUCTIVE=1`).

## Переменные окружения

Проект работает и **без** файла `.env` — во `config.js` заданы безопасные
значения по умолчанию. Если нужно изменить настройки, скопируйте образец
`.env.example` в `.env` **в корне проекта** (не в `server/`) и отредактируйте:

```bash
cp .env.example .env
```

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | Порт API. |
| `NODE_ENV` | `development` | Окружение: `development`, `production`, `test`. |
| `DATABASE_PATH` | `server/data/app.sqlite` | Путь к файлу базы (относительно корня проекта). |
| `TZ` | `Europe/Moscow` | Запасной часовой пояс, если в БД ещё нет настройки студии. |
| `SESSION_TTL_HOURS` | `168` | Срок жизни сессии (в часах). |
| `RATE_LIMIT_MAX` | `10` | Лимит запросов входа/регистрации с одного IP за окно. |
| `RATE_LIMIT_WINDOW_SECONDS` | `300` | Длина окна rate-limit (в секундах). |
| `TRUST_PROXY` | выкл. | `1` — доверять заголовку `X-Forwarded-For` (только за своим прокси). |
| `ALLOW_DESTRUCTIVE` | выкл. | `1` — разрешить `db:reset`/`seed` при `NODE_ENV=production`. |

Файл `.env` в Git не попадает (см. `.gitignore`).

Настройки студии (часовой пояс, общие часы работы, шаг сетки слотов и время
жизни удержания) хранятся **в базе**, а не в `.env`, и меняются через API.
Рабочая админ-панель для этих настроек появится в следующей итерации.

## Отладочный фронтенд

`test-frontend/` — это не часть продукта, а инструмент для ручной проверки API.
Он собран на чистом JS без сборки и покрывает все роли:

- **Вход / регистрация** — логин, регистрация клиента, вывод текущего пользователя.
- **Услуги и мастера** — каталог, фильтр мастеров по услуге.
- **Запись** — выбор услуг и мастера, свободные слоты на дату, удержание слота,
  создание записи; при занятом времени показывает ближайшие свободные слоты.
- **Личный кабинет** — «мои записи», детали, перенос и отмена.
- **Админка** — все записи с фильтрами, управление услугами и мастерами,
  настройки студии. Это отладочный экран; рабочая админ-панель появится в
  следующей итерации.

Ошибки API выводятся текстом прямо на странице.

### Зачем отдельный сервер-прокси

Браузер запрещает межсайтовые запросы без CORS-заголовков, а API их не отдаёт.
Поэтому `test-frontend/server.js` отдаёт страницу и прозрачно проксирует
`/api/*` на backend: для браузера и фронтенд, и API выглядят как один origin, и
сессионная cookie работает без дополнительных настроек.

## API — краткий обзор

Публичные:

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/services` | Список активных услуг. |
| `GET` | `/api/masters?serviceId=` | Список мастеров (можно отфильтровать по услуге). |
| `GET` | `/api/studio` | Публичные настройки студии. |
| `GET` | `/api/masters/:id/slots?date=&serviceIds=` | Свободные слоты мастера на дату. |

Требуют входа (cookie `sid`):

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/auth/register` | Регистрация клиента. |
| `POST` | `/api/auth/login` | Вход. |
| `POST` | `/api/auth/logout` | Выход. |
| `GET` | `/api/auth/me` | Текущий пользователь и связанные `masterId`/`clientId`. |
| `POST` | `/api/holds` | Удержание слота на время оформления. |
| `GET` / `DELETE` | `/api/holds/:id` | Проверка / освобождение удержания. |
| `POST` | `/api/bookings` | Создание записи. |
| `GET` | `/api/bookings/my` | Свои записи (у админа — все). |
| `GET` / `PATCH` | `/api/bookings/:id` | Детали / перенос записи. |
| `POST` | `/api/bookings/:id/cancel` | Отмена записи. |

Только администратор (`/api/admin/*`): записи (`GET`, `PATCH .../status`),
услуги и мастера (CRUD), связи мастера с услугами, график мастера, настройки
студии (`GET`/`PATCH /api/admin/studio`). Эндпоинты уже работают; клиентская
админ-панель появится в следующей итерации.

Время в API — ISO-8601 UTC (`2026-10-19T10:00:00Z`), длительности — в минутах,
цены — в копейках, `date` — `YYYY-MM-DD`, время графика — `HH:MM`.

```
├── test-frontend/          # отладочный SPA + dev-сервер с прокси /api
├── docs/                   # API, база данных и карта клиентских экранов
├── .env.example            # образец переменных окружения
└── .nvmrc                  # рекомендуемая версия Node (24)
```

## Если что-то не работает

- **`node:sqlite` не найден / ошибка импорта.** Скорее всего версия Node.js
  слишком старая. Проверьте `node -v`: нужно `>= 22.13.0` (лучше 24 LTS).
- **`ExperimentalWarning: SQLite is an experimental feature`.** Это не ошибка:
  встроенный SQLite в Node.js помечен экспериментальным. Предупреждение можно
  игнорировать.
- **`npm error ... ENOENT ... package.json` или `Missing script: "db:reset"`.**
  Команда запущена не из той папки. Команды `npm run ...` и `npm start` для
  backend работают только из `server/`, а для фронтенда — только из
  `test-frontend/`. Перейдите в нужную папку (шаги 2–4).
- **`EADDRINUSE` (порт занят).** Порт `3000` или `4000` уже используется.
  Закройте другой процесс или задайте в `.env` (`PORT`) и в окружении
  (`FRONTEND_PORT`) другие значения.
- **На странице отладочного фронтенда «API недоступно».** Не запущен backend.
  Сначала выполните `npm start` в `server/`, затем `npm start` в `test-frontend/`.
- **Страницы `web/` открыты через `file://`.** API не заработает: клиент
  обращается к относительному `/api`. Отдайте `web/` по HTTP с того же origin,
  что и backend, либо настройте прокси `/api`.
- **`db:reset` пишет «запрещено при NODE_ENV=production».** Это защита от
  удаления данных. Либо уберите `NODE_ENV=production`, либо добавьте
  `ALLOW_DESTRUCTIVE=1` в `.env`.
